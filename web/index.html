What is Mattmoss?
A little history.

A screensaver that makes its own pictures. Mattmoss fills the screen with flowing, abstract colour patterns. Weighted source points create a mathematical field, and a cycling palette makes its contours appear to move. There is no recorded animation playing underneath.

From Windows in 1996. The original Mattmoss Screen Saver 1.0.0.1 was a Windows screensaver whose embedded attribution reads “© 1996 HyperDyne Pty Ltd Australia.” Screensavers displayed moving images while a computer was idle, originally helping prevent static images from burning into CRT displays.

Reconstructed, not recovered. This WickedAILabs edition rebuilds the animation in Rust from analysis of the original Windows executable. The same renderer powers the desktop app and this WebAssembly browser version, with modern smooth colour interpolation and crossfades. It is new source code, not the original program running in an emulator, and the original executable is not bundled.

Inside the colour field

The maths
behind Mattmoss.

No photographs. No video. Each of the 640 × 480 pixels gets a number, and that number chooses a colour.

01 / Place the sources

A few points. Endless contours.

The first pattern starts with four weighted points; later patterns use three to ten. Each weight is a nonzero integer from −4 to 4. Positive and negative contributions reinforce or cancel, bending the field into different shapes.

02 / Measure the field

Turn direction into a number.

At every pixel, the renderer adds a horizontal contribution, u, and a vertical contribution, v, from each source. Their combined magnitude becomes a repeating palette index. This is an artistic field, not a gravity simulation.

magnitude = trunc(√(u² + v²)) & 65535

Divide by a band divisor, then take the remainder modulo 236. A larger divisor spreads the colour bands farther apart.

03 / Move the palette

The points stay. The colours wander.

Illustrative brightness envelope · 236 palette entries

A sine-shaped envelope makes the palette bright at both ends and dark near the middle. Shifting the palette phase moves these bands across the fixed field; changing the base RGB colour gives them new hues. That is the secret of the apparent flow.

04 / Dissolve into the next

A little modern softness.

a = t² × (3 − 2t)

This smoothstep curve blends the previous frame into a new one without an abrupt start or stop. A transition takes one simulation second—about four seconds at the default ¼× speed. Crossfades and fractional palette interpolation are modern additions, bypassed in historical interlace mode.

A closer look at the original arithmetic

For a source at (px, py) with weight w, and a pixel at (x, y):

dx = px − x; dy = py − y
d = dx² + dy²
h = trunc(dx × dy / 2)
u += trunc(w × dx × h / d)
v += trunc(w × dy × h / d)
index = (magnitude / band_divisor) % 236
E(i) = trunc(16384 × (1 − sin(3.14 × i / 235)))

u and v start at zero for each pixel. Truncation discards the fractional part towards zero. The renderer preserves signed 32-bit wrapping arithmetic and the original literal 3.14, rather than substituting π. If the squared distance is zero, it returns the previous field value; a negative wrapped magnitude-square maps to zero in this port.

These details matter: replacing the calculation with ordinary floating-point maths changes the image. A matching seed, controls and time steps reproduce a session, but host sine and square-root implementations can differ across platforms.
